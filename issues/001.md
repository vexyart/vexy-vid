# Issue 001: PyAV and opencv-python dylib conflict on macOS

## Description

On macOS, both PyAV (`av`) and `opencv-python` bundle their own copies of FFmpeg's `libavdevice` dylib. This produces objc warnings at startup:

```
objc[PID]: Class AVFFrameReceiver is implemented in both
  .../av/.dylibs/libavdevice.62.1.100.dylib and
  .../cv2/.dylibs/libavdevice.61.3.100.dylib.
This may cause spurious casting failures and mysterious crashes.
```

## Impact

- **Cosmetic only** — no functional impact observed
- Warnings appear on every CLI invocation on macOS
- Does not affect Linux or Windows

## Mitigation

- Import `av` before `cv2` in `frames.py` (already implemented)
- Consider switching to `opencv-python-headless` which may bundle fewer FFmpeg libs

## Status

Open — cosmetic issue, low priority
